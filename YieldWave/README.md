# YieldWave · 红利低波股息率波段助手

针对 **中证红利低波动指数（H30269）** 按「股息率2 / D/P2」做机械波段的桌面工具。
只根据最近约 42 个交易日（约 2 个月）的股息率动态中枢产生买卖信号，**不预测市场**，
最终只告诉你：今天买多少、卖多少、还是不动。

> ⚠️ 程序只产生交易信号，不自动下单。
> ⚠️ 投资有风险，历史回测不代表未来收益。

---

## 一、安装依赖

需要 Python 3.10+，已安装 PyQt6 的环境可直接运行。缺失依赖时安装：

```bash
pip install -r requirements.txt
```

核心依赖：`PyQt6`、`requests`、`beautifulsoup4`、`pandas`、`numpy`、`matplotlib`。
可选备用数据源 `akshare`（中证/AKShare 校验用，非必需）：`pip install akshare`。

> 如果你和我一样在 Windows + 已装好的 Python 上运行，直接用该 Python 执行 `main.py` 即可。

## 二、如何启动

```bash
python main.py
```

首次启动流程：
1. 打开 `data/yieldwave.db`（自动建表、初始化 A/B/C 仓位状态）。
2. 加载已有历史数据。
3. 若今天尚未更新过，自动尝试更新红利查一次（**网络失败不影响启动**，沿用本地数据）。
4. 计算 M20 / M42 / M60，加载本周策略。
5. 若本周尚未锁定策略，主界面提示「本周策略尚未锁定」——点「锁定本周策略」即可。
6. 计算 A/B/C 当前动作并显示主界面。

## 三、数据来源

- **主数据源：红利查（honglicha.com）** —— 页面标注其数据来源为「中证指数有限公司」。
- **备用校验源：中证官方 / AKShare**（`stock_zh_index_value_csindex(symbol="H30269")`）。
  **仅当 `config.json` 中 `csindex_enabled=true` 时才真正接线**；开启后会自动与红利查最近共同日期的股息率2 做交叉比对，
  界面显示「数据校验正常」或「数据差异告警（差异 X.XX 个百分点）」；校验结果**绝不混入主历史**，只用于提示口径偏差。

## 四、红利查实际抓取方式（已验证）

经过对 `https://www.honglicha.com/H30269/` 的实际分析，结论如下：

1. 该详情页把历史估值序列**服务端渲染**进 HTML，作为 ECharts 的 `option` JSON 内嵌在 `<script>` 中（由 `window.initDetailCharts(chartsData)` 调用）。
2. **没有公开 JSON/API 接口，也没有 XHR/Fetch 请求**；因此解析方式是请求页面 HTML（带浏览器 UA，无需登录/验证码），用正则定位每个 `option:` 之后的平衡 JSON 对象。
3. 从中找到含「DP2（计算用股本）」的图得到 **股息率2**、含「DP1」得到股息率1；含「PE2 / PE1」的图得到市盈率。按 `xAxis.data` 的日期对齐，得到逐交易日记录。
4. 截至 2026-09-04，红利查 H30269 公开页面**实测可获取 115 个交易日历史数据**（2026-03-25 ~ 2026-09-02，≈5.7 个月，**并非一年**），字段为
   `date / 股息率1 / 股息率2 / PE1 / PE2`；**页面不提供指数点位（close）**，故该字段为 None。
   **实测证据**：页面共 5 个图表块，全部固定为 115 个交易日；
   `detail.js` 只是渲染器、没有数据 API，页面也没有时间范围 / 周期 / 翻页控件。
   ⚠️ 注意：本仓库只验证了「公开页面当前返回 115 天」这一事实，**并未严格证明不存在其他公开历史接口**，
   因此不能断言这就是「历史全部」；若后续发现更长历史接口，以实际抓取为准。
5. 程序首次运行即把能拿到的历史全部写入本地库，之后每日增量 UPSERT；只要持续每日更新，
   本地库会随窗口滑动逐步累积（公开页每次只返回最近可见的一段，旧日期不会从本地丢失）。

解析实现见 `yieldwave/data_sources/honglicha.py`。**健壮性**：若页面结构变化导致解析不到任何记录，
`parse_html` 返回空列表，调用方显示「红利查数据抓取失败」并**保留本地旧数据，绝不清空历史**。

## 五、数据库位置

SQLite 单文件：`data/yieldwave.db`

表：
- `h30269_valuation`：`date PRIMARY KEY` + 股息率1/2 + PE1/2 + close + source + fetched_at。按日期 UPSERT，永不删除更早历史。
- `weekly_strategy`：每周锁定策略（week_id 主键）。
- `positions`：A/B/C 各仓状态（EMPTY/HOLDING、买卖日期、股息率、成交价等）。
- `trades`：用户「确认」后的成交记录（自增 id）。

## 六、如何备份

直接复制数据库文件即可（程序提供了一键备份方法）：

```python
from yieldwave.database import Database
db = Database()
print(db.backup())   # 生成 data/yieldwave.db.bak_YYYYMMDD_HHMMSS
```

也可以直接把 `data/yieldwave.db` 拷到任意安全位置。

## 七、导入 / 导出

- **导出 CSV**：`数据管理` 页「导出 CSV」，生成 `exports/H30269_dividend_yield_history.csv`（全部历史）。
- **导入 CSV**：`数据管理` 页「导入 CSV」，按日期 **UPSERT**（已存在日期更新，新日期插入，不删除旧历史）。整表替换属于危险操作，需二次确认并显式传入 `replace=True`。
- **去重 / 缺失交易日检查 / 手工增改**：均在「数据管理」页；不提供「一键清库」，任何删除都需二次确认。

## 八、M42 含义

- **M42 = 最近 42 个有效交易日（不是自然日）的 dividend_yield_2 中位数。**
- 同时计算 M20 / M42 / M60；日常交易主基准只用 **M42**。
- 若数据库不足 42 个交易日，程序用现有数据计算 M_N 并在界面明显显示「数据热身中：当前 XX / 42 个交易日」。
- 数字口径：所有股息率/PE 一律以**百分数**存储（4.77 表示 4.77%，不是 0.0477）；偏移量单位为**百分点**（如 `buy_offset=0.02` 表示 M42 + 0.02 个百分点，即 4.90 → 4.92）。

## 九、A/B/C 机械交易规则

仓位结构（总资金 = 100%）：
- **核心仓 60%** = 核心1 20% + 核心2 20% + 核心3 20%：长期持有，**程序绝不自动建议卖出**，只在 UI 手动「已建仓」后计入实际仓位。
  - **核心仓 60% 不再被默认当作「已持有」**：实际权益仓位 = 当前真正处于 HOLDING 的核心档 + 波段档之和；只有你确认买入的核心档才计入。
  - 核心三档的**建仓分位 `build_percentile`（50/65/80）为「待进一步回测确认」的初值，UI 会明确标注，非已验证最优参数**。
- **波段仓 40%** = A 仓 8% + B 仓 12% + C 仓 20%，各自独立记录 EMPTY/HOLDING。
  - **越跌越买**：股息率越高（越便宜）对应仓位越大，故 A(8%) < B(12%) < C(20%)。

默认参数（全在 `config/config.json`，不写死在代码里）：

| 仓位 | 类型 | 仓位% | 买入线 | 卖出线 |
|------|------|------|--------|--------|
| A | 波段 | 8%  | M42 + 0.02 | M42 − 0.01 |
| B | 波段 | 12% | M42 + 0.07 | M42 − 0.04 |
| C | 波段 | 20% | M42 + 0.12 | M42 − 0.11 |
| 核心1 | 核心(手动) | 20% | — | — |
| 核心2 | 核心(手动) | 20% | — | — |
| 核心3 | 核心(手动) | 20% | — | — |

机械判定（单向，绝不重复买 / 空仓提示卖）：
- EMPTY 且 `当前股息率 >= 买入线` → **买入**（该仓位）。
- HOLDING 且 `当前股息率 <= 卖出线` → **卖出**（该仓位全部）。
- 其余情况：空仓等待 / 继续持有。

**周度锁定**：每周第一个交易日或点击「锁定本周策略」时，按当时 M42 生成整周固定的 A/B/C 买卖线；
即便周中 M42 变化也不改本周阈值，下一个自然周才能重新锁定。主界面同时显示「实时滚动 M42」与「本周锁定 M42」。

**信号确认**：正式信号只基于「最新已公布的有效日度股息率2」，并标记数据日期；程序不假装是实时股息率。
「实时估算模式」默认关闭（见 `config.json`）。

**成交记录**：每笔成交同时保存「信号数据日期 `signal_data_date`」（官方股息率2 数据日期）与「成交日期 `execution_date`」（你确认当天），二者可能不同；
并记录**本周锁定的 M42 与买卖线**，而非用抓取值当场重新计算，保证回看成交时看到的就是当时锁定的策略。

## 十、回测与参数优化

- `回测/优化` 页可对窗口（20/30/42/50/60）与各仓偏移做参数回测，统计轮数、各仓交易次数、持有天数、股息率口径信号表现等。
- **没有指数点位/全收益数据时，胜率(资金)/收益率/最大回撤/年化 等字段统一显示「缺少价格数据，无法计算」，绝不伪造资金收益。**
- 回测统计中的 **「股息率信号完成率」** 指「买入时股息率高于卖出时（均值回归完成）」的比例，**不是真实资金盈利胜率**；
  真实资金收益由 `portfolio_backtest.py` 在具备指数点位/全收益数据时统一计算。
- **参数优化**尊重你的实际需求排序，但**不预设「年均 6~9 次」之类的具体次数目标**（那是未经验证的粗略期待，会随数据窗口与参数大幅变化）；
  优化时绝不为追求历史最高收益而选一年只交易 1~2 次的参数。
